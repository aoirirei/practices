# Практическая работа №8 — вариант 1

## Запуск

Нужен JDK 17 или новее. Исходный пакет ru.edu.pr05 сохранён. Откройте целиком папку распакованного архива в VS Code. Исходники уже лежат в starter_project/src; ничего переносить не нужно.

Из папки архива:

```bash
cd starter_project
bash run_selfcheck.sh
bash run.sh
```

Если терминал уже находится в starter_project, выполняйте только две команды bash. На Windows запускайте run_selfcheck.bat и run.bat. Единственный каталог сборки — starter_project/out. Его нет в архиве: он появится при компиляции. Для GitHub он исключён через .gitignore.

Минимальная длина причины 10 после strip, String.length.

## Пояснения по заданию

Проверка входа: BusinessTrip.validateData проверяет обязательные поля и порядок дат, доменные методы проверяют статус до данных операции.

Разбор ошибочного фрагмента: setStatus позволяет пропустить согласование, причину и календарную проверку. Вместо него используются submit, approve, reject, cancel, complete.

Ключевое правило и локальное изменение: Изменение длины причины затрагивает MIN_REASON_LENGTH. Завершение требует APPROVED и today > end; в дату окончания ещё запрещено.

Activity-диаграмма соответствует действиям и проверкам модели. В практике 7 дополнительно показан общий сценарий создания, ввода позиций, расчёта и подтверждения. class_partial содержит все существенные классы. Файлы сохранили исходные названия partial, но незавершённых блоков в них нет.
