# Практическая работа №6 — вариант 1

## Запуск

Нужен JDK 17 или новее. Исходный пакет ru.edu.pr03 сохранён. Откройте целиком папку распакованного архива в VS Code. Исходники уже лежат в starter_project/src; ничего переносить не нужно.

Из папки архива:

```bash
cd starter_project
bash run_selfcheck.sh
bash run.sh
```

Если терминал уже находится в starter_project, выполняйте только две команды bash. На Windows запускайте run_selfcheck.bat и run.bat. Единственный каталог сборки — starter_project/out. Его нет в архиве: он появится при компиляции. Для GitHub он исключён через .gitignore.

## Индивидуальная часть

Финансовый порог принят равным 10 денежным единицам. Формулировка «значение или модификатор 10» не уточняет операцию; трактовка указана явно, исходный порог 500000 заменён на 10.

## Пример ввода

```text
9;true;LOW;false
10;true;LOW;false
500000;true;HIGH;true
exit
Ожидается: FAST_TRACK, FINANCE_REVIEW, SECURITY_REVIEW. Можно вводить несколько заявок подряд.
```

## Пояснения по заданию

Проверка входа: ApprovalRouter.validate проверяет неотрицательную сумму и наличие риска; Main проверяет текстовые поля.

Разбор ошибочного фрагмента: Проверка urgent перед containsPersonalData пропускает обязательный SECURITY_REVIEW. Правильный порядок: personal, HIGH, финансовый порог, urgent, STANDARD.

Ключевое правило и локальное изменение: Изменение финансового порога затрагивает FINANCE_LIMIT. На Activity-диаграмме показан тот же порядок ранних возвратов.

Activity-диаграмма соответствует действиям и проверкам модели. В практике 7 дополнительно показан общий сценарий создания, ввода позиций, расчёта и подтверждения. class_partial содержит все существенные классы. Файлы сохранили исходные названия partial, но незавершённых блоков в них нет.
