# Принципиальные решения

1. MAX_QUANTITY = 10 находится в OrderItem и применяется и к новой, и к объединённой позиции. При повторе id позиции объединяются, но несовпадающие название или цена считаются конфликтом. Каталог OrderService возвращает один и тот же неизменяемый Product для одного описания id и отклоняет конфликтующие определения в рамках экземпляра сервиса. Order дополнительно проверяет конфликт при прямом добавлении Product.

2. OrderItem сделан неизменяемым: increase возвращает новый OrderItem, исходный объект не меняется. Это осознанное изменение исходной сигнатуры void increase(int). Order заменяет позицию только после всех проверок; getItems возвращает List.copyOf(items). Внешний код не может менять ни список, ни его элементы. Product и Employee тоже неизменяемы. Поэтому confirm защищает весь состав заказа, включая ранее полученные ссылки. Итог каждый раз считается по текущим позициям, поля total нет.

Дополнительные договорённости: пустой заказ разрешено подтвердить, поскольку запрета в условии нет. Повторный confirm отклоняется. Удаление отсутствующего id ничего не меняет. Отрицательные и нечисловые цены, NaN и бесконечность отклоняются. Унаследованный тип double сохранён; для промышленного денежного учёта следует применять BigDecimal с заданным округлением. Каталог товара может пополниться при ошибке количества в команде add, но состав заказа при неудачном добавлении всегда остаётся прежним.
